description: Why program cards intentionally differ from the restrained default Opus UI.
---

For program-card presentation, prioritize the user's supplied TruckingPricingCards React reference over generic taste or design-consistency recommendations.

Do not restore the shared billing-frequency section or its annual free-months offer on the official program page.

**Why:** The user subsequently selected the entire billing-frequency section and requested its deletion.

**How to apply:** Do not reintroduce the removed shared section. The user subsequently requested the bold “Billed monthly - Or pay annually and get 2 months free” note in both cards, superseding the earlier removal of card-level promotional copy.

**Why:** The user rejected multiple neutral redesigns and explicitly supplied the desired cards. The rounded silhouette, blue accents, and lower benefits panel are intentional reference treatments, not accidental style drift. Later refinements moved the gradient treatment to the plan badges.

**How to apply:** Preserve that visual identity when refining this step, using Opus palette tokens where possible. Do not normalize the cards back to a generic minimalist comparison.

The earlier request to bring back the ZIP's switcher is superseded by the user's deletion of the whole billing-frequency section.

Reference fidelity applies to the card composition and blue gradient identity, not to exaggerated decorative effects or tiny feature typography.

**Why:** The user approved the Emil-inspired polish for the official page: more readable copy and restrained effects while retaining the supplied card structure and badge/checkout-button identity.

**How to apply:** Preserve those recognizable design choices when refining this page; do not restore excessive glow or hover movement solely to match the original reference.

Do not reserve blank description or pricing height to keep cards identical.

**Why:** After approving the polish, the user explicitly rejected the large empty area between the price and checkout button, then also requested removing the empty space above the price.

**How to apply:** Let descriptions and pricing content determine their height, keeping only normal spacing between sections, even if wrapping or billing changes alter card height.

The billing switcher's selected option must have an unmistakable filled treatment and a non-color selection cue.

**Why:** The user found the reference's subtle white selected state too difficult to distinguish. Clear selection takes priority over reproducing that part of the ZIP exactly.

**How to apply:** Preserve the stronger selected/unselected distinction when refining the switcher, including its hover and disabled states. Keep the approved equal-width options and their payment-frequency descriptions, with the promotional badge below the group rather than overlaid on Yearly.

**Why:** On 2026-10-01 the user explicitly chose this separated, descriptive switcher for the official page after comparing alternatives. This supersedes the ZIP's compact switcher and floating offer badge, not the existing card design.

The savings badge is a warm promotional accent, distinct from the blue billing-selection state.

**Why:** The user requested a “hot deal” color treatment for the savings badge rather than another blue element.

**How to apply:** Keep the offer accent visually separate from selection feedback and preserve readable small text. The chosen switcher uses a soft warm pill with dark warm text; its approval supersedes the earlier orange/red gradient badge.

The card's button chooses the plan and starts checkout in one action; the program page must not have a separate navigation footer.

**Why:** On 2026-10-01 the user explicitly restored the in-card plan-choice buttons as the checkout action and removed the program page's footer, superseding the previous footer-Continue direction.

**How to apply:** Keep plan choice and checkout submission atomic, with the current billing frequency. Preserve the location page's footer; this direction applies only to the program page.

The in-card checkout buttons should match the plan badges' visual treatment, rather than the flat color of the wizard's Continue buttons.

**Why:** The user explicitly requested matching the Essentials / Pro badge style for the card buttons, then reaffirmed “keep the styling from the buttons” when approving the three-plan redesign.

**How to apply:** Keep the same badge gradient, white text, border, radius, and shadow on enabled card buttons, while preserving gray disabled states and the separate navigation styles.

The approved three-plan canvas design supersedes the earlier two-card composition, but not the original gradient checkout-button styling.

**Why:** The user approved applying the CSV-based Essential, Pro, and Works cards to the app and specifically retained the existing buttons.

**How to apply:** Preserve the three-plan feature grouping and names while keeping the original checkout actions and their loading/disabled behavior.

Use the full program names in the headings without separate Essentials or Pro badges.

**Why:** The user changed the headings to “Opus Trucking Essentials” and “Opus Trucking Pro”, then explicitly deleted both separate badges, superseding the earlier right-side badge direction.

**How to apply:** Do not restore the redundant plan-name badges. Preserve the existing checkout-button treatment independently.
